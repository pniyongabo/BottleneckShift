# Published figures and their provenance

Each figure here is regenerated from validated raw series by a committed script, so it
can be reproduced from the retained archive. The raw series are not in this repository;
see each report's artifact record for the archive name and checksum.

Every series is validated (`scripts/validate_results.py`) before any figure is drawn;
`analysis/phases.py` and `analysis/milestone3_figures.py` both call `validate_series`
first and refuse to plot an incomplete or failing series.

## Reproducing

Install the analysis extra (matplotlib), extract the verified archive, then:

```bash
python -m pip install -e '.[analysis]'

# Phase B: four series, one figure of server phases, throughput, and GPU utilization
python analysis/phases.py \
  <extracted>/results/runs/milestone3-20261003T180358Z-{prefill_heavy,decode_heavy}-{forward,reverse} \
  --summary /tmp/summary.csv --output reports/figures/milestone3-phase-b-phases.png

# Phase C: both figures from one session directory
python analysis/milestone3_figures.py \
  <extracted>/results/runs milestone3c-20261003T201214Z \
  --output-dir reports/figures
```

Figures are PNG at 150 dpi. Markers are per-repetition values and lines or bars are
medians across the three repetitions, as each figure's legend states.

## What each figure shows

- **`milestone3-phase-b-phases.png`** — per regime (`prefill_heavy`, `decode_heavy`) and
  concurrency (C1, C8): server queue/prefill/decode time as stacked bars with client
  TTFT and E2E overlaid, output throughput, and GPU utilization. Decode dominates in
  both regimes.
- **`milestone3-phase-c-crossover.png`** — `prefill_heavy` against concurrency (C1, C8,
  C16, C32): output throughput, inter-token latency p50 and p99 (log scale), and the
  share of E2E spent before the first token, with the pre-registered 0.5 threshold
  marked. Throughput saturates by C16 while the share falls, so the added latency moves
  into per-step time.
- **`milestone3-phase-c-contention.png`** — the five contention series (off, sham, duty
  0.25, duty 0.50, off again) at C1 and C8: server phases with client E2E, and
  `nvidia-smi` GPU utilization per repetition. Latency rises with duty cycle, sham and
  recovery match the baseline, and utilization barely moves.
