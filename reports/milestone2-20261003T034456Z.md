# BottleneckShift Milestone 2: controlled RTX A4000 concurrency experiment

## Result

With prefix caching disabled, greedy request-level sampling, pinned model assets, and
warm-ups at both concurrency levels, increasing maximum client concurrency from 1 to 8
increased output throughput approximately 6.5× and median end-to-end latency
approximately 18%. Both execution orders agree to within 0.1% on throughput, TPOT, and
end-to-end latency. The Milestone 1 tradeoff therefore persists under explicit
controls. Its magnitudes shift: compared with Milestone 1, concurrency-8 TTFT is
21–42% higher, while TPOT is 3–4% lower and throughput 2–4% higher in both
conditions. This milestone compares protocols; it does not attribute those shifts to
any single control, and it does not identify a hardware bottleneck.

## Terms used in this report

| Term | Meaning |
|---|---|
| TTFT | time to first token: from sending a request until its first output token arrives |
| TPOT | time per output token: (E2E − TTFT) / (output tokens − 1) |
| ITL | inter-token latency: the gap between consecutive streamed tokens of one request |
| E2E | end-to-end latency: from sending a request until its last token arrives |
| C1, C8 | maximum client concurrency: at most 1 or 8 requests in flight |
| Forward / reverse | the same conditions run in opposite orders (C1 then C8, or C8 then C1) |
| Series / pair | one server start running all warm-ups and measured runs of a config / the series of one session |
| Warm-up | unmeasured runs before measurement, excluded from analysis |
| Prefix caching | vLLM reusing stored work for repeated prompt prefixes (off in this milestone) |
| Greedy decoding | `temperature = 0`: always pick the most likely token |
| `generation_config = "vllm"` | ignore the model's own default sampling settings |

Full definitions: [`docs/glossary.md`](../docs/glossary.md).

## Interpretation and limitations

- **Replicated:** the throughput–latency tradeoff of moving from C1 to C8 appears in
  both orders and both protocols. Errors remain zero and output lengths exact. As in
  Milestone 1, two concurrency settings do not establish a saturation point, and no
  resource-contention intervention was performed.
- **Order effects are small under controls.** Forward and reverse medians agree to
  within 0.1% for throughput, TPOT, and E2E latency. Only C8 TTFT differs (47.28 vs
  44.14 ms), and its repetition ranges overlap.
- **The Milestone 1 reverse-C8 outlier pattern did not recur as such.** Reverse C8
  repetition 1 again has the highest reverse C8 TTFT (48.30 ms, vs 44.14 and
  43.15 ms), but its throughput is in line with the other repetitions (1,661 vs
  1,662 and 1,659 tokens/s); in Milestone 1 it fell to 1,568. Forward C8 TTFT instead
  rises across repetitions (45.77 → 47.28 → 48.57 ms). C8 TTFT varies by a few
  milliseconds between repetitions, with no consistent first-repetition effect.
- **Changed magnitudes, plausible but untested explanations.** C8 TTFT rose
  substantially relative to Milestone 1, while C1 TTFT fell. Disabling prefix caching
  removes the cached-prefix savings that Milestone 1's rising hit rate (to ~75–78%)
  could provide. That loss would matter most when prefills queue at concurrency 8.
  Greedy decoding without the model's repetition penalty is plausibly cheaper per
  token, consistent with lower C1 TTFT and TPOT in both conditions. Warm-ups also
  differ. Each control changed at once, and the VM allocation differs, so this report
  does not attribute the shifts to any single change.
- **The historical pair was not greedy.** It sent no request temperature, so the
  server applied the model's defaults (temperature 0.7, top_p 0.8, top_k 20,
  repetition_penalty 1.1). Milestone 1 TPOT and E2E numbers are therefore sampled-
  decoding measurements; that difference is part of the protocol change.
- **End-to-end reconstruction.** The analysis reconstructs E2E latency as TTFT plus
  summed inter-token intervals. In all 12 measured runs it matches vLLM's own
  `median_e2el_ms` to within 0.001 ms, so the reconstruction and vLLM's latency end at
  the same timestamp. Three of 1,200 measured requests record fewer than 127
  intervals despite 128 output tokens, consistent with occasional multi-token stream
  chunks. Inter-token intervals should still not be read as one decode step per token.
- **Cache-off is a deliberate, less production-like setting.** Production servers
  usually run with prefix caching enabled. Cache behavior is left as a later factor
  rather than mixed into the concurrency question.
- Shutdown-time force-kill warnings appear after each completed series, as in
  Milestone 1. Three repetitions per condition and one VM allocation support
  descriptive findings, not broad statistical generalization.

  and smoke directories and the driver-upgrade log. Steps 9–12 console logs are
  archived.
- The executed step scripts match the reviewed run plan.

## Recommended next step

Treat this pair as the Milestone 2 baseline for the bottleneck-shift study
(Milestone 3 in `experiments/roadmap.md`). Before collecting Milestone 3 data, add the
tooling prerequisites listed there: per-condition workloads, server-side `/metrics`
scrapes, and resource telemetry. Keep this protocol's controls fixed. To explain the
C8 TTFT shift relative to Milestone 1, a cache-enabled versus cache-disabled pair under
otherwise identical controls would isolate the cache effect. That comparison is
optional and not part of this milestone.
